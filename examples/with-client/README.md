# ayjnt example: with-client

Demonstrates how the Cloudflare Agents client SDK connects to a worker generated by ayjnt.

The short version: **use `basePath`, not `path`**. Without it, the client tries to hit `/agents/chat-agent/<id>` and ayjnt's worker returns 404.

## Layout

```
with-client/
├── agents/chat/agent.ts   ← the ChatAgent (server)
└── client.ts              ← a Bun script that calls the agent (client)
```

## Run it

```sh
bun install

# terminal 1 — start the worker
bun run dev

# terminal 2 — hit it
HOST=http://localhost:8787 bun run client
```

Expected output:

```
POST -> 200 { ok: true, name: 'demo-room' }
GET  -> 200 { messages: [ { role: 'user', text: 'hello from the client' } ], name: 'demo-room' }
```

The `name: 'demo-room'` in the response comes from `this.name` on the DO. That field is only populated because our generated worker entry calls `getAgentByName` — see [the gotcha](#gotcha-1-path-vs-basepath-on-the-client).

## Gotcha 1: `path` vs `basePath` on the client

The Agents client SDK builds URLs like this (from `partysocket`):

```
{protocol}://{host}/{basePath OR `${prefix}/${party}/${room}`}{path}
```

With the Agents client hardcoding `prefix: "agents"` and kebab-casing the class name:

| Client option | Resulting URL |
|---|---|
| `useAgent({ agent: "ChatAgent", name: "42" })` | `wss://host/agents/chat-agent/42` |
| `useAgent({ agent: "ChatAgent", name: "42", path: "/x" })` | `wss://host/agents/chat-agent/42/x` — `path` is an **append**, not a replacement |
| `useAgent({ agent: "ChatAgent", basePath: "chat/42" })` | `wss://host/chat/42` — **full override** |

ayjnt exposes agents at `/<route-path>/<instanceId>`, so every client connection must set `basePath`. The SDK's own docstring for the option spells it out: *"Full URL path — bypasses agent/name URL construction. When set, the client connects to this path directly. Server must handle routing manually."*

The `agent` field is still required by the SDK's type signature, but it's ignored when `basePath` is set. Pass the class name anyway so the types match.

## Gotcha 2: identity wiring on the server (handled for you)

When a client connects, the agent broadcasts a `CF_AGENT_IDENTITY` message containing `{ name: this.name, agent: kebab(ClassName) }`. The SDK uses this to know which instance it's talking to.

For the DO to have a correct `this.name`, something on the server must call `stub.setName(name)` before the request reaches the agent. Cloudflare's own `routeAgentRequest` does this via `getAgentByName` internally; a naive `namespace.idFromName(name) → namespace.get(id) → stub.fetch(...)` dispatch skips it and produces broken identity messages.

ayjnt's generated `.ayjnt/dist/entry.ts` uses `getAgentByName` for exactly this reason. You don't need to do anything — this example works out of the box. But if you ever write your own entry, remember to call `getAgentByName` (from the `agents` package), not raw `idFromName + get`.
